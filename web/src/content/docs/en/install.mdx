SpiderFolio installs with Docker Compose. It has four parts:

- **db**: the PostgreSQL 16 database (no public port).
- **app**: the API, which also serves the web app. It prepares the database on startup.
- **worker**: background jobs (emails, PDFs, search, trash…).
- Optional: **caddy** (automatic HTTPS), **gotenberg** (PDFs of controlled documents) and
  **mailpit** (test email inbox).

## Where will you install it?

Pick one option and follow only its section: each one has its own complete step by step.

| Option | What for | What you need |
| --- | --- | --- |
| [Try it on your PC](#try-it-on-your-pc) | See it working, without real data | Windows 10/11, macOS or Linux with Docker |
| [Server with your own domain](#server-with-your-own-domain) | Real use, with automatic HTTPS | A Linux server, a domain and an email server |
| [Server behind your own proxy](#server-behind-your-own-proxy) | You already have nginx, Traefik, IIS or another proxy with HTTPS | A Linux server, your proxy and an email server |

Does your company run Windows Server? See [Windows](#windows): the recommended setup is an Ubuntu
virtual machine in Hyper-V, and from there you follow the server guide.

## Try it on your PC

To see SpiderFolio working on your own computer. It's only reachable from that computer, at
`http://localhost:8080`, and emails don't go out: they land in a test inbox (Mailpit).

### 1. Install Docker

- **Windows 10/11**: install Docker Desktop as explained in
  [Windows › Try it on a Windows PC](#try-it-on-a-windows-1011-pc).
- **macOS**: install Docker Desktop and use the commands in the Linux tab.
- **Linux**: install Docker Engine (`curl -fsSL https://get.docker.com | sudo sh`).

Check that it works. It must print a version, with no errors:

```sh
docker compose version
```

### 2. Download SpiderFolio

Generate the secrets. Each command gives a different value; note which is which:

```powershell
function New-Secret([int]$Bytes) {

# MFA_ENCRYPTION_KEY
```
```sh
openssl rand -base64 32
```

</Fragment>

Each line is `NAME=value`. Find these four lines, which are empty, and paste each secret right after
the `=`, with no spaces or quotes:

```ini
POSTGRES_PASSWORD=paste-the-password-here
JWT_ACCESS_SECRET=paste-the-first-secret-here
EMAIL_ENCRYPTION_KEY=paste-the-first-key-here
MFA_ENCRYPTION_KEY=paste-the-second-key-here
```

Everything else is already set for trying it on your PC. Check that these lines say this:

```ini
APP_URL=http://localhost:8080
WEB_URL=http://localhost:8080
DOMAIN=
COMPOSE_PROFILES=mail
SMTP_HOST=mailpit
SMTP_PORT=1025
```

Save the file. `DOMAIN` stays empty: it's only used with automatic HTTPS.

### 4. Start it

```sh
docker compose up -d
```

The first time it downloads the images (a few minutes). To follow the app's progress:

```sh
docker compose logs -f app
```

When the `API lista` (API ready) line shows up, it's done. Leave the log with `Ctrl+C` (the app keeps
running).

### 5. Check

<OsTabs>
<Fragment slot="windows">

```powershell
curl.exe http://localhost:8080/api/health
```

</Fragment>
<Fragment slot="linux">

```sh
curl http://localhost:8080/api/health
```

</Fragment>
</OsTabs>

It must answer:

```json
{"status":"ok"}
```

If it doesn't answer or shows an error, see [Common problems](#common-problems) and
[Troubleshooting](/en/docs/troubleshooting).

### 6. Create your account

1. Open `http://localhost:8080` in the browser and click **Create account**. You become the owner.
2. The verification email lands in the test inbox: open `http://localhost:8025` and click the link in
   the email.

Continue with [First administrator](/en/docs/first-administrator).

### To shut it down

```sh
docker compose down
```

The data is kept: `docker compose up -d` starts it again. To also delete all the test data:
`docker compose down -v` (it can't be undone).

## Server with your own domain

For real use: anyone signs in over HTTPS at an address like `https://docs.your-company.com`. Caddy
gets and renews the certificate automatically (Let's Encrypt).

### 1. Prepare the server

You need:

- A **Linux** server (for example, Ubuntu 24.04 LTS) with **2 vCPUs and 4 GB of RAM** for a company
  of up to about 200 people. Details in [Server requirements](/en/docs/server-requirements).
- A **domain** (or subdomain) with a DNS `A` record pointing to the server's public IP.
- Ports **80 and 443** open to the server (firewall and router).
- An **email (SMTP) server**: your company's or a transactional service (Resend, Postmark, Amazon
  SES…). Have the host, port, user and password at hand.

Install Docker and check that it works:

```sh
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
```

Sign out and back in (to use `docker` without `sudo`). Then:

```sh
docker compose version
```

### 2. Download SpiderFolio

```sh
git clone https://github.com/spiderjad/SpiderFolio.git
cd SpiderFolio/deploy
```

Type all the following commands in that `deploy` folder.

### 3. Create the configuration (`.env`)

**With the script (recommended).** Choose option **2 (Server with your own domain)** and enter the
domain and the email details:

```sh
./setup.sh
```

If you used the script, continue with step 4.

**By hand.** Copy the example and generate the secrets. Each command gives a different value; note
which is which:

```sh
cp .env.example .env
chmod 600 .env
# POSTGRES_PASSWORD (letters and digits only)
openssl rand -hex 24
# JWT_ACCESS_SECRET
openssl rand -base64 48
# EMAIL_ENCRYPTION_KEY
openssl rand -base64 32
# MFA_ENCRYPTION_KEY
openssl rand -base64 32
```

Open `.env` with `nano .env` (save: `Ctrl+O` and `Enter`; exit: `Ctrl+X`). Each line is
`NAME=value`: type the value right after the `=`, with no spaces. Change these lines (with your
domain instead of `docs.your-company.com`):

```ini
APP_URL=https://docs.your-company.com
WEB_URL=https://docs.your-company.com
DOMAIN=docs.your-company.com
COMPOSE_PROFILES=https
POSTGRES_PASSWORD=paste-the-password-here
JWT_ACCESS_SECRET=paste-the-first-secret-here
EMAIL_ENCRYPTION_KEY=paste-the-first-key-here
MFA_ENCRYPTION_KEY=paste-the-second-key-here
SMTP_HOST=smtp.your-provider.com
SMTP_PORT=587
SMTP_USER=your-smtp-user
SMTP_PASS='your-smtp-password'
MAIL_FROM="SpiderFolio <no-reply@your-company.com>"
```

- `DOMAIN` goes without `https://`; `APP_URL` and `WEB_URL`, with `https://`.
- `WEB_URL` is the project's public website (documentation and legal pages). On your own
  installation, use the same value as `APP_URL`.
- `SMTP_PASS` goes in single quotes, so characters like `$` or `#` are read as they are.

Keep a copy of `.env` somewhere safe: without `MFA_ENCRYPTION_KEY` nobody can sign in again with their
two-step verification. All the variables are in [Configuration](/en/docs/configuration).

### 4. Start it

```sh
docker compose up -d
docker compose logs -f app
```

When the `API lista` (API ready) line shows up, it's done. Leave the log with `Ctrl+C`. Caddy gets
the certificate within the first minute; you can see it with `docker compose logs caddy`.

### 5. Check

On the server itself, without going through HTTPS:

```sh
curl http://localhost:8080/api/health
```

And from outside, with your domain:

```sh
curl https://docs.your-company.com/api/health
```

Both must answer:

```json
{"status":"ok"}
```

If the first one answers and the second doesn't, check the DNS and ports 80 and 443
([Proxy and HTTPS](/en/docs/proxy-and-https)). If neither answers, see
[Troubleshooting](/en/docs/troubleshooting).

### 6. Create your company

Open your domain in the browser, click **Create account**, verify your email and you become the
owner. Continue with [First administrator](/en/docs/first-administrator) and schedule
[backups](/en/docs/backups) before you load real data.

## Server behind your own proxy

For when you already have a proxy with HTTPS (nginx, Traefik, IIS, a load balancer…). SpiderFolio
doesn't open ports 80 and 443: it listens on `127.0.0.1:8080` and your proxy forwards traffic to it.

### 1. Prepare the server

You need:

- A **Linux** server (for example, Ubuntu 24.04 LTS) with **2 vCPUs and 4 GB of RAM** for a company
  of up to about 200 people. Details in [Server requirements](/en/docs/server-requirements).
- Your **proxy with HTTPS** and the address people will use (for example,
  `https://docs.your-company.com`).
- An **email (SMTP) server**: your company's or a transactional service (Resend, Postmark, Amazon
  SES…). Have the host, port, user and password at hand.

Install Docker and check that it works:

```sh
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER
```

Sign out and back in (to use `docker` without `sudo`). Then:

```sh
docker compose version
```

### 2. Download SpiderFolio

```sh
git clone https://github.com/spiderjad/SpiderFolio.git
cd SpiderFolio/deploy
```

Type all the following commands in that `deploy` folder.

### 3. Create the configuration (`.env`)

**With the script (recommended).** Choose option **3 (Server behind your own proxy)** and enter the
URL and the email details:


If you used the script, continue with step 4.

**By hand.** Copy the example and generate the secrets. Each command gives a different value; note
which is which:

```sh
# JWT_ACCESS_SECRET
```

Open `.env` with `nano .env` (save: `Ctrl+O` and `Enter`; exit: `Ctrl+X`). Each line is
`NAME=value`: type the value right after the `=`, with no spaces. Change these lines (with your
address instead of `docs.your-company.com`):

```ini
APP_URL=https://docs.your-company.com
WEB_URL=https://docs.your-company.com
DOMAIN=
COMPOSE_PROFILES=
POSTGRES_PASSWORD=paste-the-password-here
JWT_ACCESS_SECRET=paste-the-first-secret-here
EMAIL_ENCRYPTION_KEY=paste-the-first-key-here
MFA_ENCRYPTION_KEY=paste-the-second-key-here
SMTP_HOST=smtp.your-provider.com
SMTP_PORT=587
SMTP_USER=your-smtp-user
SMTP_PASS='your-smtp-password'
MAIL_FROM="SpiderFolio <no-reply@your-company.com>"
```

- `DOMAIN` and `COMPOSE_PROFILES` stay empty: your proxy provides HTTPS.
- `WEB_URL` is the project's public website (documentation and legal pages). On your own
  installation, use the same value as `APP_URL`.
- `SMTP_PASS` goes in single quotes, so characters like `$` or `#` are read as they are.
- If the proxy is on **another machine**, change `HTTP_BIND=127.0.0.1` to this server's internal IP,
  and allow port 8080 only from the proxy.

Keep a copy of `.env` somewhere safe: without `MFA_ENCRYPTION_KEY` nobody can sign in again with their
two-step verification. All the variables are in [Configuration](/en/docs/configuration).

### 4. Start it

```sh
docker compose up -d
docker compose logs -f app
```

When the `API lista` (API ready) line shows up, it's done. Leave the log with `Ctrl+C`.

### 5. Set up your proxy

Your proxy must forward all traffic for your address to `http://127.0.0.1:8080` (or to the IP you
set in `HTTP_BIND`), with the `X-Forwarded-For` and `X-Forwarded-Proto` headers, and accept large
file uploads. There are nginx and Traefik examples in [Proxy and HTTPS](/en/docs/proxy-and-https).

### 6. Check

On the server itself, without going through the proxy:

```sh
curl http://localhost:8080/api/health
```

And through your proxy:

```sh
curl https://docs.your-company.com/api/health
```

Both must answer:

```json
{"status":"ok"}
```

If the first one answers and the second doesn't, the problem is in the proxy. If neither answers,
see [Troubleshooting](/en/docs/troubleshooting).

### 7. Create your company

Open your address in the browser, click **Create account**, verify your email and you become the
owner. Continue with [First administrator](/en/docs/first-administrator) and schedule
[backups](/en/docs/backups) before you load real data.

## Windows

### Try it on a Windows 10/11 PC

1. **Turn on WSL2.** Open PowerShell as administrator (right-click Start › Terminal (Admin)) and run:

   ```powershell
   wsl --install
   ```

   Restart the PC when asked.

2. **Install Docker Desktop** from [docker.com](https://www.docker.com/products/docker-desktop/).
   During setup, keep **Use WSL 2** checked.
3. **Open Docker Desktop** and wait until the bottom left says **Engine running**.
4. **Check** in a normal PowerShell window:

   ```powershell
   docker compose version
   docker run --rm hello-world
   ```

   The second command must print `Hello from Docker!`.

5. Follow [Try it on your PC](#try-it-on-your-pc) with the commands in the **Windows (PowerShell)**
   tab.

### Production at a company with Windows Server

Docker on Windows isn't meant for a server that runs 24/7: Docker Desktop needs a signed-in user
session, updates itself and requires a paid license at larger companies; and Docker on Windows Server
runs Windows containers, not the Linux ones SpiderFolio uses.

The recommended setup is an **Ubuntu virtual machine in Hyper-V**, which is included in Windows
Server. The virtual machine starts with the server and SpiderFolio runs inside it as on any Linux.

1. **Turn on Hyper-V.** In PowerShell as administrator (the server restarts):

   ```powershell
   Install-WindowsFeature -Name Hyper-V `
     -IncludeManagementTools -Restart
   ```

2. **Create a virtual switch** connected to the network, so the virtual machine gets its own IP.
   Find your network adapter's name with `Get-NetAdapter` and use it instead of `Ethernet`:

   ```powershell
   New-VMSwitch -Name "External" `
     -NetAdapterName "Ethernet" -AllowManagementOS $true
   ```

3. **Download Ubuntu Server 24.04 LTS** (an `.iso` file) from
   [ubuntu.com/download/server](https://ubuntu.com/download/server) and save it, for example, as
   `C:\ISO\ubuntu-24.04-live-server-amd64.iso`.
4. **Create the virtual machine** (2 vCPUs, 4 GB of RAM, 100 GB disk):

   ```powershell
   $vm = @{
     Name               = "spiderfolio"
     Generation         = 2
     MemoryStartupBytes = 4GB
     NewVHDPath         = "C:\Hyper-V\spiderfolio.vhdx"
     NewVHDSizeBytes    = 100GB
     SwitchName         = "External"
   }
   New-VM @vm
   Set-VMProcessor spiderfolio -Count 2
   Set-VMMemory spiderfolio -DynamicMemoryEnabled $false
   $iso = "C:\ISO\ubuntu-24.04-live-server-amd64.iso"
   Add-VMDvdDrive spiderfolio -Path $iso
   Set-VMFirmware spiderfolio `
     -SecureBootTemplate MicrosoftUEFICertificateAuthority `
     -FirstBootDevice (Get-VMDvdDrive spiderfolio)
   Set-VM spiderfolio -AutomaticStartAction Start `
     -AutomaticStopAction ShutDown
   Start-VM spiderfolio
   ```

5. **Install Ubuntu.** Open the virtual machine's console (Hyper-V Manager › double-click
   `spiderfolio`) and follow the installer with the default options. Check **Install OpenSSH server**
   to manage it over SSH later. When it's done, remove the installation disc:

   ```powershell
   Get-VMDvdDrive spiderfolio | Remove-VMDvdDrive
   ```

6. **Give the virtual machine a fixed IP** (a reservation in your DHCP or in the Ubuntu installer).
   Inside the virtual machine you can see it with `ip -4 addr`.
7. **Follow the server guide** inside Ubuntu: [Server with your own domain](#server-with-your-own-domain)
   (the router or firewall must forward ports 80 and 443 to the virtual machine's IP) or
   [Server behind your own proxy](#server-behind-your-own-proxy) (for example, IIS with ARR on the
   Windows Server, pointing to `http://virtual-machine-IP:8080`, with `HTTP_BIND` set to that IP).

[Backups](/en/docs/backups) run inside Ubuntu, as on any server; copy the backup folder outside the
virtual machine.

### Common problems

- **Docker Desktop isn't running.** The error says
  `failed to connect to the docker API at npipe:////./pipe/dockerDesktopLinuxEngine` or
  `The system cannot find the file specified`. Open Docker Desktop and wait for **Engine running**.
  If it never finishes starting, run `wsl --update` and restart; if it's still the same, turn on
  virtualization in the BIOS.
- **Port in use.** The error says `port is already allocated` or `ports are not available`. See which
  program is using the port:

  ```powershell
  Get-NetTCPConnection -LocalPort 8080 -State Listen |
    ForEach-Object { Get-Process -Id $_.OwningProcess }
  ```

  Close it or use another port: in `.env`, `HTTP_PORT=8081`, `APP_URL=http://localhost:8081` and
  `WEB_URL=http://localhost:8081`. If the busy one is 8025 (Mailpit), change `MAIL_UI_PORT`. Then run
  `docker compose up -d`.
- **Notepad saved it as `.env.txt`.** Docker doesn't find it and says `POSTGRES_PASSWORD` is missing.
  Check and rename it:

  ```powershell
  Get-ChildItem -Force
  Rename-Item .env.txt .env
  ```

  To avoid it, open the file with `notepad .env` and, if you use **Save as**, choose
  **All files (\*.\*)** as the type.
- **Line endings.** If you copy `setup.sh` or `.env` from Windows to a Linux server, they may arrive
  with Windows line endings (CRLF) and fail with `bad interpreter` or odd values. On the server,
  convert them:

  ```sh
  sed -i 's/\r$//' setup.sh .env
  ```

  The `.env` that `setup.ps1` writes already uses Linux line endings.
- **"Running scripts is disabled on this system".** Run the script as the guide says, with
  `powershell -ExecutionPolicy Bypass -File .\setup.ps1`: it doesn't change anything on the system.

## Optional

- **PDFs of controlled documents** (Gotenberg): in `.env`, add `pdf` to `COMPOSE_PROFILES` (for
  example, `COMPOSE_PROFILES=https,pdf`) and set `GOTENBERG_URL=http://gotenberg:3000`. Then run
  `docker compose up -d`. Without Gotenberg everything works the same, except that PDF. See
  [Gotenberg](/en/docs/gotenberg).
- **Files on S3** (R2, MinIO, AWS…): `STORAGE_DRIVER=s3` and the `S3_*` variables. By default files
  go to the `files` volume. See [Storage](/en/docs/storage).
- **Bian, the AI assistant**: `BIAN_ENABLED=true` and `ANTHROPIC_API_KEY` (queries are billed to your
  Anthropic account).
- **Limits**: there are none by default. Each company sets storage, file size, kept versions and
  audit retention in Administration › Limits and usage.
- **Installation back office** (`/internal`: companies and their usage): flag whoever runs the server
  (by their email) and ask them to turn on two-step verification:

  ```sh
  docker compose exec db psql -U spiderfolio -c \
    "UPDATE \"User\" SET \"isStaff\" = true
     WHERE email = 'you@example.com';"
  ```

- **Build the image yourself** (for example, with plugins): from the `deploy` folder,
  `docker compose build` and then `docker compose up -d`.
